# Versioned cross-platform settings store (schema v2)

Ticket: 04
Wave: A
Blocked by: 01
Status: open

Decision source: 12 (read it in full; every rule below is from it), plus 03 (foreign paths fall back without overwrite; corrupt settings -> timestamped backup + safe defaults + visible recovery).

Deliverables - settings_store.py (pure, no Tk/openvino imports):
- SettingsStore(path, platform=sys.platform, base_dir=None) with load() (returns the raw document, migrating a v1/flat file in memory: schema_version 2 + empty "shared"/"platforms"/"backends" namespaces beside the untouched flat keys; never deletes or rewrites flat keys), save() atomic: temp file in the same directory, fsync, os.replace, serialised behind an RLock; never lowers schema_version; unknown keys and namespaces copied through untouched; schema_version stamped 2 on write.
- get(key, default=None): resolution order platforms.<current os> -> shared -> legacy flat -> derived default table. set(key, value, scope="auto"): on win32 writes the flat key and mirrors; on linux writes ONLY to platforms.linux (machine-bound keys) or shared (portable keys) and never touches the flat block. Document which keys are portable (shared) vs machine-bound.
- Paths: the keys model_dir, gpu_model_dir, model_path, gguf_path, chatllm_dir, crispasr_dir, ffmpeg_path: a value under base_dir is stored RELATIVE with forward slashes in "shared"; outside base_dir it is machine-bound and lives in platforms.<os>; get() resolves relative values against base_dir and returns None for a foreign platform path that does not exist here (fall back to discovery) WITHOUT overwriting it.
- ui_scale: canonical key ui_scale_percent (int). Reading a legacy ui_scale: value < 10 is a multiplier (x100), >= 10 is already a percent. On win32 every write of ui_scale_percent also mirrors the float ui_scale (percent/100). Provide ui_scale_multiplier() and ui_scale_percent() helpers for the two surfaces.
- Unhonourable values: validate(key, value) with a small validator table (backend in supported set for this platform, cpu_model_size in {"0.6B","1.7B"}, scale is a number in 25..400, device present when a devices list is supplied); an unhonourable value is ignored for the session (get returns the derived default) and left on disk; store.session_ignored -> list of (key, reason_code) for the capability snapshot.
- backend: absent means unset - no seeding. derived_default("backend") is platform-derived: win32 keeps whatever webview_backend._seed_defaults derives today (read it and replicate the derivation as a function, do not persist), linux -> openvino CPU with 0.6B.
- Corruption: unparsable JSON -> rename to settings.json.corrupt-<YYYYmmdd-HHMMSS>, start from defaults, store.recovered = backup path (surfaced later by the capability snapshot).
Wiring (behaviour-preserving on Windows, keep diffs small): webview_backend.py reads/writes settings.json in many places (grep SETTINGS_FILE / settings.json: _seed_defaults 165, _settings_raw 240, _persisted_backend ~468, _persist_backend 812, set_model ~917, get_settings 1110 (scale read at 1126), set_settings 1137, _persist_setting 1319). Route them through one SettingsStore instance; _seed_defaults stops persisting a backend (derive at runtime); _persisted_backend returns the derived fallback when unset. app.py:1131 reads ui_scale as a float multiplier: use the store's multiplier helper; setting.py:585 likewise. Do not restructure the Tk UI.
Tests (tests/test_settings_store.py): v1 file -> v2 roundtrip preserves every flat key byte-for-byte in meaning; linux set() never writes flat keys; win32 set() mirrors; resolution order; ui_scale heuristics both ways and win32 mirror; relative path storage and foreign-path fallback without overwrite; corrupt file -> backup + defaults + recovered; atomic save leaves no partial file when the writer is interrupted (simulate by patching os.replace to raise and asserting the original is intact); unhonourable value ignored for session but still on disk; schema_version never lowered; unknown namespace preserved.
