# Define first-run ownership and recovery

Type: grilling
Status: resolved
Blocked by: 01, 03, 12

## Question

What is the precise first-run contract across OS packages, the Python virtual environment, models, VAD, FFmpeg, and optional cloudflared, including discovery, downloads owned by the application, progress, retry, partial files, offline use, and actionable failure messages?

## Answer

Ubuntu first run has three owners and no fourth. The **user** owns the apt layer and uv itself, both documented; **uv** owns the Python environment; the **application** owns models and VAD, and nothing else. uv is not in Ubuntu 24.04's archive, so installing it is a documented prerequisite alongside `ca-certificates`, `ffmpeg`, `xdg-utils`, and `python3-tk`.

**One dependency source.** `pyproject.toml` plus `uv.lock` are authoritative. `requirements.txt` keeps its current path and meaning but is generated by `uv export` instead of hand-edited, so the Windows `pip install -r` flow and `build_venv.bat` are untouched and the two declarations cannot drift. uv uses Ubuntu's **system Python 3.12** with Tk 8.6 — the interpreter ticket 01 actually probed — rather than downloading one. A uv-managed interpreter ships Tk 9.0, on which customtkinter is unverified while the browser backend still imports the Tk graph at module load; it is deferred, not adopted.

**Failure is tiered.** `run.sh` gates launch on `uv sync --check`, a local no-network assertion, and refuses on drift while naming the command that fixes it; `uv sync` is idempotent setup, so a half-finished setup reads as "not set up" rather than "set up wrong". Anything that blocks app readiness fails fast in the terminal and exits non-zero. Everything else degrades into ticket 03's capability snapshot. FFmpeg absent and no runnable browser both degrade: audio-file transcription still works without FFmpeg, and a browserless launch prints its loopback URL, which is also exactly what the headless CI job needs. Fatal is reserved for "the server genuinely cannot serve".

**Partial files stop lying.** Downloads land in `<name>.part` and `os.replace` into position, so a file at its real name is complete by construction. This closes the hole where `_download_file` wrote straight to `dest` in `ab`/`wb` mode and `_file_is_real()` — which only rejects Git-LFS pointers — waved a truncated `config.json` through as ready, and it closes it across every file of every manifest rather than only the three 0.6B `.bin` files that carry SHA-256.

**Retry distinguishes transient from offline.** A mid-stream failure retries three times with backoff, resuming from the `.part` via `Range` and keeping the existing primary-to-fallback repository switch. A connect or DNS failure means no network: stop immediately, no retry storm, say so. Either way the partial survives and an explicit Resume restarts where it left off, honouring ticket 11's resumable partials. On Linux the TLS chain ends at system trust and fails with a `ca-certificates` remedy; the `CERT_NONE` rung — justified by frozen-EXE CA breakage that a source install cannot suffer — is removed on Linux only, leaving Windows unchanged.

**Downloads become visible work.** A download is a job in ticket 09's registry with its full reconnect contract, in a **download lane** exempt from the single-runner rule; that rule exists for CPU inference contention, not network I/O, so fetching 1.7B never blocks transcribing with 0.6B. Jobs are validated at submit: requesting speaker separation whose models are absent is refused with the download offered as an explicit action, replacing today's `_ensure_diarization` behaviour of downloading inside a running transcription and then completing successfully without diarizing. The registry therefore never records a completed-but-degraded job.

**Messages are a contract, not prose.** The terminal preflight runs before any language preference is readable, so it prints English and Chinese together. Capability reasons and remedies become a code plus parameters that `i18n.js` renders in the user's chosen language, resolving the collision between ticket 03 — the backend is the sole source of reasons and remedies — and `i18n.js`'s current rule that backend dynamic messages stay untranslated.

Two constraints carried in from earlier decisions hold unchanged: VAD is a shared prerequisite ensured for **both** model sizes (ticket 01), closing the gap where the 1.7B-only path neither checks nor downloads it; and Linux never downloads Windows binaries, so the `ffmpeg.exe` ZIP and `cloudflared-windows-amd64.exe` paths stay disabled (tickets 01 and 03).

Adopting uv is a repo-wide packaging change larger than this ticket's question strictly implies. It is accepted deliberately: `uv export` keeps Windows byte-compatible with its current flow, and a single lock is what makes the Ubuntu CI job's environment provable.
